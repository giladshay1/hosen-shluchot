# חוסן שלוחות – אפליקציה לראשי שלוחות

אפליקציית רשת (PWA) לראשי השלוחות של מרכז חוסן גליל מערבי. היא כוללת מצב חירום עם 10 סוגי אירועים וצ'קליסטים, 6 השאלות הראשונות, הודעות בעברית ובערבית, דיווח לעדי, יומן אירוע וסיכום, תזכורות, הערכת מצב, אנשי קשר ופליירים.
האפליקציה **לא מחוברת לטבלת המעקב** (מגרסה 1.7.0 הוסרו "קליטת קבוצה מהודעה" ו"השבוע שלי" וכל הקריאה והכתיבה לטבלה).
האפליקציה מחוברת לשרת Google Apps Script. היא עובדת גם בלי רשת: פעולות שנעשו בלי חיבור נשמרות בתור ונשלחות כשהחיבור חוזר.

---

## 1. פרסום ב-GitHub Pages (פעם אחת, כ-10 דקות)

1. נכנסים ל-github.com ויוצרים מאגר חדש (New repository).
   - שם מומלץ: **`hosen-shluchot`**
   - **Public**. בחשבון חינמי GitHub Pages עובד רק עם מאגר ציבורי. בקוד אין סיסמאות, מפתחות או טלפונים אמיתיים.
2. **Add file ← Upload files**. גוררים את **כל התוכן של התיקייה `pwa`**, כלומר הקבצים והתיקיות עצמם ולא את התיקייה `pwa`. הקובץ `index.html` צריך להיות בשורש המאגר.
   - את התיקייה `qa/` (צילומי מסך מהבדיקות) אפשר לא להעלות.
   - חשוב להעלות גם את הקובץ הריק `.nojekyll`.
3. לוחצים **Commit changes**.
4. **Settings ← Pages**. תחת Source בוחרים **Deploy from a branch**. תחת Branch בוחרים **main** ואת התיקייה **/(root)**, ואז **Save**.
5. אחרי דקה או שתיים הכתובת מופיעה בראש העמוד:
   `https://<שם-המשתמש>.github.io/hosen-shluchot/`

### התקנה בטלפון
- **אנדרואיד (Chrome)**: פותחים את הכתובת ובוחרים ⋮ ← "התקנת אפליקציה" או "הוספה למסך הבית".
- **אייפון (Safari בלבד)**: פותחים את הכתובת ובוחרים שיתוף ← "הוסף למסך הבית".
- בכניסה הראשונה צריך רשת. מאותו רגע הצ'קליסטים, הנוסחים והפליירים הבסיסיים זמינים גם בלי רשת.

## 2. כתובת השרת (API)

הכתובת מוגדרת **במקום אחד בלבד**, בשורות הראשונות של `app.js`:

```js
const API_URL = 'https://script.google.com/macros/s/AKfycb…/exec';
```

- **עדכון קוד בשרת בלי לשנות כתובת**: ב-Apps Script בוחרים Deploy ← Manage deployments ← ✏️ ← Version: **New version** ← Deploy. הכתובת נשארת כפי שהיא, ואין צורך לגעת באפליקציה.
- אם נוצרה פריסה חדשה (New deployment), נוצרה גם כתובת חדשה. במקרה כזה:
  1. מעדכנים את `API_URL` ב-`app.js`.
  2. מעלים את הגרסה (ראו סעיף 4).
  3. מעלים ל-GitHub את `app.js` ואת `service-worker.js` (ב-GitHub: פותחים את הקובץ ← ✏️ ← מדביקים ← Commit).

## 3. הוספת משתמשים

המשתמשים נשמרים בשרת, בלשונית `Users` של גיליון האפליקציה. בגיליון נשמר רק hash של הסיסמה.

1. פותחים את פרויקט ה-Apps Script.
2. מוסיפים פונקציה זמנית, למשל:
   ```js
   function addUsersOnce() {
     adminAddUserLogin('גלעד שי',     'ים',     'gilad',  '__________', true);
     adminAddUserLogin('איילי אוקרט', 'נחלים',  'ayali',  '__________', false);
     adminAddUserLogin('אמיר ואכד',   'ציר 70', 'amir',   '__________', false);
     adminAddUserLogin('מרואן פלאח',  'הר',     'marwan', '__________', false);
   }
   ```
   - השלוחה היא אחד מהערכים `ים`, `נחלים`, `ציר 70`, `הר`. לפיה נקבעות הרשויות.
   - **שם המשתמש** לא רגיש לאותיות גדולות וקטנות, ורווחים בהתחלה ובסוף לא נחשבים. **הסיסמה** רגישה לאותיות גדולות וקטנות. מומלץ לבחור סיסמה של 8 תווים לפחות, ולכל משתמש סיסמה אחרת.
   - הפרמטר האחרון (`true`) מסמן מנהל מערכת.
3. בוחרים את הפונקציה ולוחצים **Run**. אחרי ההרצה **מוחקים את הפונקציה** ושומרים, כדי שהסיסמאות לא יישארו בקוד.
4. מוסרים לכל ראש שלוחה את שם המשתמש והסיסמה שלו.

**טלפון שאבד או החלפת סיסמה**: מריצים `adminRevokeUser('<user_id>')` (ה-user_id נמצא בלשונית Users), וכל הכניסות של המשתמש מתנתקות. אפשר גם לשנות את `active` ל-FALSE. לסיסמה חדשה מוסיפים את המשתמש מחדש עם הסיסמה החדשה ומשביתים את השורה הישנה.

## 4. עדכון האפליקציה (קבצים, נוסחים, פליירים)

בכל עדכון של קובץ מעלים את מספר הגרסה **בשני מקומות**, אחרת בטלפונים תישאר הגרסה הישנה מהמטמון:
- `service-worker.js`: `const VERSION = 'v1.0.1';`
- `app.js`: `const APP_VERSION = '1.0.1';`

בפתיחה הבאה מופיע בטלפון הכפתור "גרסה חדשה זמינה – לחץ לעדכון".

- **תוכן** (צ'קליסטים, נוסחי הודעות, קטלוג פליירים, מנחים): קבצי JSON בתיקייה `data/`.
- **פליירים מצורפים**: התיקייה `flyers/` כוללת 17 קבצים (כ-2.3MB), כולם להפצה לציבור: 15 פוסטים לפייסבוק לחירום ו-2 דפי "איך לדבר עם ילדים" (עברית וערבית). שאר הפליירים מופיעים בקטלוג בלבד, ובשיתוף שלהם נשלח נוסח בלי קובץ.
  - פליירי "מוקד סיוע" **לא נכללו**, כי הם מיועדים להפצה רק בתיאום עם היחידה הקלינית.
  - כדי להוסיף פלייר: שומרים JPG ברוחב של עד 1200px בתיקייה `flyers/`, מוסיפים לרשומה שלו ב-`data/flyers.json` את השדה `"file": "flyers/<id>.jpg"`, ומוסיפים את הנתיב לרשימה `CONTENT` ב-`service-worker.js`.

## 5. מה נשמר איפה

| נתון | שרת (Google Sheets) | טלפון |
|---|---|---|
| משתמש, שלוחה, רשויות | ✔ (`login`) | עותק |
| אנשי קשר | ✔ מקור האמת (`contacts.*`) | עותק לעבודה בלי רשת |
| אירועים וסימוני צ'קליסט | ✔ (`events.create` / `setStep` / `close`) | עותק מלא, כולל 6 השאלות וסיכום |
| יומן אירוע והערכות מצב | נשלחים ללשונית `Log` | ההיסטוריה המוצגת |

- **AI בשרת**: הכפתורים "ניתוח AI בשרת" מופיעים רק כשהשרת מדווח שיש מפתח Claude, כלומר `mockAi=false` ב-`ping`. עד אז עובדים הניתוח הבסיסי בטלפון והכפתור "נתח עם Claude", שמעתיק את הנוסח למינוי Claude האישי.
- **סטטוס הסנכרון** מוצג כתווית קטנה: "מסונכרן", "N ממתינות", "לא מקוון" או "נכשלו". לחיצה על התווית מסנכרנת מיד.
- **יציאה** מוחקת מהטלפון את נתוני המשתמש ואת התור, ולכן אפשר לצאת גם בטלפון משותף. אם יש פעולות שעדיין לא נשלחו, האפליקציה מבקשת אישור לפני היציאה.
- **מצב הדגמה** (קישור במסך הכניסה): נתוני דמה בלבד, בלי חיבור לשרת. שימושי להצגה.

## 6. בדיקה מקומית

```bash
cd pwa && python3 -m http.server 8765
# בדפדפן: http://localhost:8765
```

## 7. מבנה הקבצים

```
index.html            מעטפת הדף
app.js                כל האפליקציה (כאן גם API_URL)
api.js                חיבור לשרת, תור offline (IndexedDB), מטמון קריאה
styles.css            עיצוב (כיוון A)
service-worker.js     עבודה בלי רשת
manifest.webmanifest  הגדרות ההתקנה
data/*.json           תוכן: אירועים, נוסחים, פליירים, תפקידים, מענים, ישובים, פרומפטים
assets/               לוגואים
icons/                אייקונים (192, 512, maskable, apple-touch)
flyers/               17 פליירים מצורפים
```
